# 架构

扩展面向小型 Racket 程序和日常编辑。VS Code 前端直接注册语言 provider，通过 JSON Lines 协议调用独立的 Racket 后端。使用说明见 [README](../README.md)，原生回调清单见 [Check Syntax 接入](CHECK_SYNTAX.md)。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `src/extension.ts` | 注册功能与扩展生命周期 |
| `src/documents.ts` | 文本快照、字符位置转换与范围比较 |
| `src/workspace.ts` | 分析会话、依赖失效、诊断与缓存 |
| `src/protocol.ts` | 后端数据类型、请求、输出解码与进程终止 |
| `src/bindings.ts` | 绑定身份、关系图、光标绑定选取与跨文件身份匹配 |
| `src/navigation.ts` | 定义、引用、高亮、大纲与工作区符号 provider |
| `src/rename.ts` | 重命名 provider、修改收集与重新展开检查 |
| `src/editor.ts` | 补全、悬停、文档、签名、格式化与范围 provider |
| `src/source.ts`、`src/structural.ts` | 源码定义、参数模型、表达式导航与结构修改 |
| `src/highlighting.ts`、`src/relations.ts` | 高亮、关系树与注解快照 |
| `src/runtime.ts` | 文件运行与原生 REPL |
| `src/organize.ts`、`backend/organize.rkt` | 教学代码中的重名定义整理 |
| `backend/semantic.rkt` | 完整展开、Check Syntax collector、作用域补全与回调 |
| `backend/lexical.rkt`、`backend/source.rkt` | 官方 lexer、括号树、缩进、导航与 reader 结构 |
| `backend/common.rkt` | 协议收发、源码加载环境、依赖记录与错误位置 |
| `backend/main.rkt` | 按启动参数选择 semantic、lexical 或 organize worker |

## 进程与协议

`src/extension.ts` 创建 `Workspace` 并注册各项功能；`src/protocol.ts` 的 `Worker` 启动独立 Racket 进程。各 worker 的请求如下：

| Worker | 请求 | 职责 |
| --- | --- | --- |
| `semantic` | `analyze`、`complete`、`private-definition`、`rename`、`documentation` | 展开模块，保留绑定、补全上下文与原生回调 |
| `lexical` | `document`、`format`、`navigate`、`expression`、`modules` | 处理当前文本、缩进、表达式与模块路径 |
| `organize` | `organize` | 为重名定义整理生成文本修改 |

请求使用 `{ id, method, params }`，响应携带相同 `id`、`result` 或 `error`，以及读取依赖。用户代码的输出作为独立 `output` 事件传输，避免与 JSON Lines 响应混杂。公共后端模块显式导出共享函数和环境结构，不对外暴露协议端口与内部锁。

## 分析与会话

语义和词法分析使用独立 worker。语义分析依次读取模块、完整展开、调用 `make-traversal`、收集注解与补全模型。Check Syntax 的名称冲突闭包保留在原 worker 中，通过 ID 调用。

| 入口 | 行为 |
| --- | --- |
| 打开、保存、手动检查 | 启动语义检查；有效的打开缓存可复用 |
| `available` | 获取或等待已有检查，不启动新检查；结果可能包含分析错误 |
| `current` | 同步获取匹配当前文本的分析结果，补全用它避免等待检查 |
| `withSemantic` | 显式跨文件查询按需分析目标，并在查询期间保留会话 |
| `lexical` | 获取当前版本的词法数据及绑定该版本的请求入口 |

`racket/load` 返回 `mode: "syntax"`，不展开文件主体，不构造 Check Syntax 注解和语义补全模型。词法编辑继续可用。

会话存在不等于语义可用：需要绑定的功能还必须判断 `analysis.complete` 和 `analysis.mode`，不能把检查失败或 syntax 模式当作完整模块分析。

### 失效与取消

未保存编辑使当前文件及依赖它的结果失效。处理中的请求、失败分析和依赖不明确的会话保守失效；无关的已完成分析可以保留。保存、磁盘变化和可执行文件配置变化使语义缓存全局失效。失效本身不安排新的检查；匹配当前编辑器内容的磁盘保存通知不会重复撤销保存请求。

手动检查只替换当前文件的语义会话。待处理条目在读取快照前注册，取消既能阻止尚未启动的 worker，也能终止运行中的检查。被替换的请求不能重新发布结果。

worker 统一处理异常退出、协议错误、stdin 错误与显式关闭，并结束待处理请求。响应必须包含结果或错误，并对应仍在途的请求；请求准备阶段的异常也通过 Promise 返回。`Worker.pending` 保存仍在等待响应的调用方，`inFlight` 记录已发送但尚未返回的请求；取消调用方等待不会让后端立即停止，也不会提前将 worker 标为空闲。

异步操作按各自范围使用以下约束：

| 入口 | 约束 |
| --- | --- |
| `Workspace.assertTrusted()` | 扩展未释放且工作区受信任 |
| `Workspace.assertCurrent(session)` | 语义会话的世代仍有效且 worker 正在运行 |
| `Workspace.assertGeneration(generation, token)` | 跨文件操作期间没有工作区变更，也未取消 |
| `LexicalSession.assertCurrent()` | 文档未关闭、版本匹配、缓存条目未被替换或标为过期，且 worker 正在运行 |

词法会话的 `request` 在发送和返回时都应用同一约束；调用方跨越其他异步步骤后仍需判断当前文档和会话。结构命令另行约束编辑器与选区，避免将结果应用到用户后来选择的位置。

### 缓存

`semanticEntries` 中每个文件的 `SemanticEntry` 保存检查请求、快照、worker 和返回的会话；失效时移除整个条目，不另行维护一份结果索引。`lexicalEntries` 保存词法更新队列，`recentlyClosed` 保存最近关闭的文件，`activeQueries` 记录临时保留会话的查询。读取依赖 `workerDependencies` 与监听器 `dependencyWatchers` 分开管理。请求完成与分析成功是两回事，失败分析也可保留错误结果。

历史补全名称和显示颜色独立于该条目：前者只有名称与插入文本，后者只有文本、范围和显示分类。二者都不能作为当前绑定信息使用。

最近关闭的最多 8 个文件保留语义与词法进程及分析结果；查询正在使用的会话暂不淘汰。重新打开时比较文本并绑定新的编辑器版本；更早淘汰的文件重新检查。关闭时丢弃未保存内容会使相关缓存失效。缓存不跨窗口重载持久化。

编辑和保存可复用当前文件的词法进程。文档更新串行发送，跳过排队时已被取代的快照。后端每次重建 namespace、源码覆盖、textoid 和 reader 结构，并释放上一份文档 custodian 管理的资源。词法会话在请求前后检查有效性，避免复用进程后串用不同文本。

## 源码、位置与依赖

后端位置按规范化换行后的 Racket 字符计数，零起点、右端不含。`Snapshot` 保留原文与规范化文本：`utf16Offsets` 将后端字符位置映射到原文偏移，`lineStarts` 记录原文行首，以处理 CRLF 和补充平面字符。`rawOffset` 用于原文替换，`position`、`range` 用于编辑器位置；不能直接把后端字符位置当作 JavaScript 字符串下标。提供给编辑器的范围必须属于对应文档版本；只需识别文件类型时直接读取文本，不创建坐标快照。

每个分析环境拥有独立 namespace 和源码覆盖层。模块加载器优先使用打开文档的文本，并为工作区模块绕过编译缓存。后续请求刷新尚可能读取的编辑器覆盖文本，不重新展开已加载的 namespace。已准备好覆盖层的请求直接使用该数据。

源码加载器和 security guard 记录读取依赖；guard 不限制读写权限。每次响应携带最新依赖集合，外部文件 watcher 随活跃依赖建立和释放。路径依赖用于判断未保存编辑的影响，但不能覆盖时间、环境变量、网络等任意宏输入。

错误诊断只使用异常明确提供的源码位置，按实际文件发布。多个会话对同一文件的诊断合并去重，并保留各自归属。无位置错误保留在输出和状态中，不用运行栈猜测错误表达式。

跨文件查询直接收集常见源码后缀；其他候选只读取最多 4 KiB 的文件头识别语言声明，不整份载入数据文件。非标准后缀文件的声明需要出现在这段文件头中；已打开的 Racket 文档仍直接纳入查询，`.rktd` 数据文件除外。

## 绑定与重命名

本地身份来自 Check Syntax 的实际绑定边；预测关系只用于展示。跨模块身份由定义文件、子模块、名称和定义 phase 组成。导入回调中的 phase shift 不能直接充当定义 phase，需从匹配的 `identifier-binding` 恢复；身份未知或同一源码范围对应多个 phase 时拒绝重命名。

重命名流程：

1. 根据绑定关系选择范围，处理导入别名和前缀。
2. 用 Racket reader 读取新名称，调用原生名称冲突闭包。
3. 从展开后的导出信息判断定义是否私有。已确认的本文件私有定义只处理当前文件；其他情况按跨文件流程收集修改。
4. 构造修改前后快照和内存覆盖层，在独立 namespace 中重新展开相关模块。
5. 映射旧位置，比较实际绑定边、定义目标和跨模块跳转。展开失败、绑定改变或映射不明确时拒绝修改。
6. 返回一个可撤销的 `WorkspaceEdit`。

单次操作按分析会话缓存名称解码结果；冲突回调仍按实际目标执行。每条修改的字符长度变化与共同前后缀只计算一次，供原绑定图中的所有位置复用。空符号名称与缺失名称分别处理。协议统一使用 `RenameResult`，字段含义见 [Check Syntax 接入](CHECK_SYNTAX.md#名称与冲突请求)。重新展开是重命名功能本身的一部分，准备阶段不写入源码文件。引用查询同样可跳过已确认私有定义的跨文件扫描。

`rename-in` 的原始名称变化不等于本地别名改名。修改收集先区分两者，仅将实际改名的绑定送入冲突闭包；别名源名称的修改仍参与后续重新展开检查。

重名定义整理独立于语义重命名。它使用标准 reader 和保守的作用域遍历，沿源码顺序分配版本名称，不展开用户代码。名称映射同时决定替换文本与报告的定义数量，不维护额外计数。局部体先展开 body 层级的 `begin`，收集内部 `define` 并建立递归作用域，再遍历初始化式和表达式；嵌套函数仍不享有顶层函数的直接自递归例外。前端一次提交全部修改；命令行入口则逐文件直接写入。

## 补全、签名与文档

精确补全从展开语法和核心导入形式收集候选，以 `module->exports` 获取导出信息，并通过 `identifier-binding` 和 `free-identifier=?` 核对作用域、phase 与 binding space。同一最小源码范围对应多个展开上下文时，候选必须在所有上下文中一致。补全不通过实例化用户模块的运行时主体获取信息。

候选按 phase 存入 `free-id-table`，以真实绑定归并分类和查找调用目标，避免逐个候选扫描全表，也不丢失不同拼写的导入别名关系。前端传入当前拼写前缀，后端先筛选再判断作用域。已确认的本地函数传递 `function` 类别；无法确认的导入值仍保持 `variable`。导入候选不携带 require 位置，调用目标只从本地定义候选中产生。

`completionNames` 单独保存成功分析中的名称和插入文本，不保留位置、作用域或 worker。当前分析不可用时，标准 Racket 中按输入前缀筛选历史名称，以普通文本候选返回。关闭文件、更换可执行文件和扩展释放时清除这份缓存。

词法补全的引用上下文区分普通引用与准引用深度；unquote、unquote-splicing、unsyntax 和 unsyntax-splicing 只退出对应的一层准引用。历史名称可以用于已退出引用的表达式，但仍不代表当前作用域已经完成分析。

模块路径补全优先于名称补全。前端用当前 lexer token 识别标准 Racket 模块体中的 `require`，以及 `only-in`、`except-in`、`rename-in`、`prefix-in`、`for-syntax`、`for-template`、`for-label`、`for-meta`、`for-space`、`combine-in` 的模块参数。它允许未闭合列表，但跳过注释、引用数据和不明确的形式。其他语言依赖当前语义分析的 require 注解。

后端通过 `find-module-path-completions/explicit-cache` 查询路径，先精确解析已输入的父目录，再补全最后一段。前端只替换当前路径段，目录补全后再次触发候选查询。

本地签名结合 reader 参数表、已确认的标准形式和真实调用绑定，支持可选、关键字、剩余参数与 `case-lambda`。`racket/keyword-transform` 用于恢复可选和关键字调用的原始操作符。没有当前完整分析时不返回签名。

文档定位使用现有会话的路径与锚点；打开文档无需读取摘要。悬停和文档签名通过同一会话查询 Scribble 蓝框内容。`rkt-` 代码片段独立于语义补全。

## 高亮与源码视图

显示缓存保存最近成功分析的原始着色和编辑后移动的着色，仅包含文本、UTF-16 范围与显示分类。编辑按原始偏移从后往前调整范围，丢弃受影响标记；全文恢复原样时恢复原始着色。检查失败保留显示缓存，成功后替换。它不参与绑定查询或修改。

边界插入先平移而不直接删除旧颜色。移动后的范围需在当前词法结果中重新对齐 token 起止边界，避免删除分隔符后给一个新标识符分段套用旧颜色；灰淡装饰也等待这一步。当前分析的原生子 token 标注不受该旧显示过滤限制。

高亮按位置扫描与 token 相交的标注，再筛选覆盖当前片段的标注；重叠原生样式按原始注解顺序取优先级。参数和函数类别沿实际绑定边传播，契约等特殊样式仍优先。词法注释与字符串不被语义颜色覆盖。`set!d` 表示绑定被赋值，不作为每次引用都在写入的标记。

参数、函数的正体颜色装饰只用于生成它们的文档版本。未使用代码统一由灰淡装饰呈现，遵循 `editor.showUnused`；其透明度覆盖原生 `Unnecessary` 显示，避免诊断存在与失效时切换样式。诊断本身仍随语义失效清除。

Outline 使用 reader 范围和已确认的定义分类；分析失败时仅显示中性顶层结构。由于 VS Code 按版本和 provider 身份缓存大纲，分析完成与失效后会重新注册 provider，同一微任务内的刷新合并处理。工作区符号合并原生定义与同一范围、名称和 phase 的大纲类别。关系树展示原生与补充注解，可跟随光标筛选；它的光标背景装饰只在关系视图可见时生效。

## 结构编辑与格式化

`structure-header-end` 使用标准 reader 跳过前导空白和注释，通过局部 readtable 识别受支持的 `#lang`，不加载项目 reader。结构读取、表达式注释、格式化和重名整理共用此入口。reader 失败时保留此前读出的 forms。

表达式选择、包裹和求值优先复用 reader 路径；扩大选择保留操作数与引用前缀各自的层级，单个表达式求值和包裹则把直接引用前缀与操作数一起处理。没有可用 reader 节点时回退到官方词法导航；该导航本身也处理引用前缀。方向键导航与签名调用范围仍使用 lexer 的括号信息。

结构修改结合 reader 节点和 lexer 括号范围，保留注释及引用前缀。纳入、移出和解包裹要求普通列表及明确边界；表达式注释由 lexer 定位 `#;`，再由 reader 确定完整数据范围。多光标修改先排除歧义和重叠，再一次提交；异步查询或选择括号后重新检查文档、选区与会话。基于 reader 坐标的修改共用提交入口，提交失败时报错；包裹非空选区仍直接使用编辑器坐标。修改后的光标位置按源码顺序累加偏移，再恢复原光标顺序。

格式化跳过行首位于跨行词法单元内部的行。非文件末尾的行首端点不包含下一行；文件末尾的空行则纳入格式化。标准 Racket 没有自定义缩进回调时，复用 token、括号树和逐行位置映射；其他语言按其缩进接口处理并按需重新分词。

## 运行与交付

运行进程和分析 worker 独立。REPL 通过原生终端执行 `racket --repl --eval '(enter! (file "…"))'`，表达式作为单独 argv 传递。会话保存终端、文件 URI 和加载时文本；求值前检查文本、选区和会话身份，再通过 `sendText` 发送。加载成功与是否正等待输入由用户判断。

文件运行复用普通 shell 终端，通过 shell integration 跟踪执行，忙时拒绝新命令。命令按 shell 规则转义，工作目录不一致时先切换目录。两个入口都先保存当前文件，依赖从磁盘读取。

构建、打包与 `Scheme/Racket` 配置安装命令见 [README](../README.md#构建与本地安装)。发行包包含 JavaScript 和 Racket 后端源码，排除源码映射与本机编译缓存，另附 SHA-256 文件。编译与安装不代表运行验收，测试由项目所有者负责。
